# MovieTok — «TikTok по фильмам» для sapkeflykino
## Роадмап разработки + распределение по агентам

> Бесконечная вертикальная лента **трейлеров** с TikTok-подобной рекомендательной
> системой, которая учится по неявному поведению (время просмотра, % трейлера,
> быстрый свайп, переход «Смотреть»). Снизу постер + кнопка «Смотреть» → дип-линк
> в существующий плеер. Лайки / сохранить / «не интересно».

---

## 0. Ключевое архитектурное решение
**Не форкаем готовый клон** (все устарели 2022, без лицензий, прибиты к чужим бэкендам).
**Собираем из кубиков поверх того, что уже есть.** У нас уже готово ~70%:
Next.js-сайт, FastAPI-бэкенд, авторизация, избранное, TMDB-данные, рекомендатель.
Нужно добрать 30%: UX ленты + движок рекомендаций по поведению.

### Что откуда берётся
| Кусок | Источник |
|---|---|
| Трейлеры | TMDB `/movie/{id}/videos` → YouTube-ключи → **embed** (не перехостим — легально, 0 стоимости) |
| Фичи фильмов (жанры, ключевые слова, актёры, год, популярность) | TMDB (уже тянем) |
| Лента-компонент (web) | `reinaldosimoes/react-vertical-feed` (MIT, активный): scroll-snap + IntersectionObserver autoplay + onEndReached |
| Лента-компонент (mobile, фаза 4) | `TheWidlarzGroup/react-native-video-feed` (MIT, активный): виртуализация + preload + snap + HLS |
| Модель данных лайков/комментов | по образцу `napthedev/toptop-clone` (tRPC/Prisma schema — берём только схему) |
| Кандидаты для ленты | существующий рекомендатель + популярное |
| Ранжирование | НАШ онлайн вектор вкуса + контекстный бандит (`river`, Python) |
| Плеер для «Смотреть» | существующий `/movie/[id]` (дип-линк) |
| Авторизация / лайки / сохранить | существующая авторизация + favorites/storage |

### Поток данных (как всё работает)
```
[юзер листает /feed]
      │ свайп, dwell, %досмотра, тап «Смотреть»
      ▼
POST /api/feed/events  ──►  feed_events (Postgres)
      │                          │
      │                          ▼
      │                  обновляется user_taste (вектор вкуса, EMA по награде)
      ▼
GET /api/feed?cursor=  ──►  кандидаты (сущ. рекомендатель + популярное)
                              → скоринг (вкус × фичи фильма) + бандит (15% разведки)
                              → разнообразие/дедуп (не повторять тайтл, мешать жанры)
                              → курсор-пагинация → батч из N трейлеров + префетч
      ▼
[лента бесконечна, подстраивается за 10–20 свайпов]
```

## 1. Технологический стек
- **Frontend:** Next.js (есть) + `react-vertical-feed` + YouTube IFrame API (muted autoplay, preload).
- **Backend:** FastAPI/Next API routes (есть) + Postgres (новые таблицы).
- **Рекомендатель:** `river` (Python online-ML, прямо в FastAPI) — контекстный бандит + EMA-вектор вкуса. Без тяжёлого ML, без обучения «ночью».
- **Хранилище:** только метаданные + события (трейлеры embed'ятся с YouTube — ничего не храним = ноль legal/диск рисков).

## 2. Модель данных (Postgres)
```sql
-- сырые сигналы (одна строка на показ трейлера)
feed_events(
  impression_id PK, user_id, movie_id, ts,
  dwell_ms, watch_ms, pct_watched, completed bool,
  fast_skip bool,           -- свайп < 2 c
  tap_watch bool,           -- нажал «Смотреть»  (🥇 золотой сигнал)
  played_full bool,         -- реально запустил фильм
  liked bool, saved bool, not_interested bool,
  reward float              -- посчитанная награда (см. §3)
)
-- вектор фич каждого фильма (из TMDB)
item_vectors(movie_id PK, vec jsonb)   -- жанры, ключевые слова, актёры, декада, популярность
-- онлайн вектор вкуса юзера (обновляется каждый свайп)
user_taste(user_id PK, vec jsonb, n_events int, updated_at)
-- что уже показывали (дедуп бесконечной ленты)
feed_seen(user_id, movie_id, ts, PRIMARY KEY(user_id, movie_id))
```

## 3. Формула награды (TikTok-взвешенная)
```
reward = 1.0*pct_watched + 0.8*completed
         + 2.5*tap_watch + 4.0*played_full      ← золото (конверсия в просмотр)
         + 0.5*liked + 0.8*saved
         - 1.2*fast_skip - 2.5*not_interested
reward = tanh(reward / 3)   # сжать в [-1, 1]
```
Время и % досмотра — основа; переход «Смотреть» → реальный просмотр — главная цель;
быстрый свайп и «не интересно» — сильные минусы. Лайк — слабый (как в TikTok).

## 4. API
```
GET  /api/feed?cursor=<opaque>     → { items: [{movie_id, trailer_key, poster, title, ...}], next_cursor }
POST /api/feed/events              → батч сигналов (идемпотентно по impression_id)
POST /api/feed/like  /save  /skip  → явные действия (или внутри events)
```

## 5. ФАЗЫ
**Фаза 1 — MVP ленты (1–2 недели):** трейлеры из TMDB/YouTube, вертикальный свайп,
логирование сигналов, онлайн вектор вкуса + epsilon-greedy бандит, постер + «Смотреть»,
лайк/сохранить, бесконечность + дедуп. **Цель:** проверить, листают ли и конвертятся ли.

**Фаза 2 — коллаборативка (после накопления данных):** implicit-ALS / `gorse`
(«похожим людям зашло»), подмешиваем к контентному скорингу, не заменяем.

**Фаза 3 — последовательная модель (если упрёмся в потолок):** SASRec (RecBole) —
«что показать следующим по твоей сессии».

**Фаза 4 — мобильное приложение:** перенос ленты в Expo через `react-native-video-feed`.

## 6. РАЗБИВКА ПО АГЕНТАМ (каждый — своя зона)

### 🟦 Agent A — Трейлер-каталог (источник контента)
- TMDB `/movie/{id}/videos` → выбрать лучший трейлер (official > trailer > ru→en fallback), YouTube-ключ.
- Индекс трейлеров: какие фильмы имеют трейлер, кэш ключей, фильтр «нет трейлера».
- Эндпоинт-резолвер ключа по movie_id. **Зависимости:** TMDB (есть). **Отдаёт:** список movie_id с trailer_key.

### 🟩 Agent B — Бэкенд: feed API + события
- Postgres-таблицы (§2), миграции.
- `POST /api/feed/events` (идемпотентно), `GET /api/feed?cursor=` (заглушка-ранжирование сначала).
- Курсор-пагинация + дедуп через `feed_seen`. **Зависимости:** Postgres. **Отдаёт:** API-контракт для A,C,D.

### 🟨 Agent C — Фронтенд: лента `/feed`
- Интеграция `react-vertical-feed`, YouTube IFrame (muted autoplay, preload следующих 3–5).
- Оверлей: постер + название + кнопка **«Смотреть»** (дип-линк `/movie/[id]`), лайк/сохранить/«не интересно».
- **Сбор сигналов:** dwell, watch_ms, pct_watched, fast_skip, tap_watch → батч в `POST /events` (beacon).
- Бесконечный скролл через `next_cursor`. **Зависит от:** B (API). **Отдаёт:** рабочий UX.

### 🟧 Agent D — Рекомендательный движок
- `item_vectors` из TMDB-фич; онлайн `user_taste` (EMA по награде, обновление каждый свайп).
- Контекстный бандит (`river`, epsilon-greedy/LinUCB) — explore/exploit + холодный старт.
- Скоринг кандидатов (вкус × фичи), разнообразие/MMR (не 3 одинаковых жанра подряд), дедуп.
- Интеграция СУЩЕСТВУЮЩЕГО рекомендателя как генератора кандидатов (не выбрасываем).
- **Зависит от:** B (события), A (каталог). **Отдаёт:** ранжирование для `GET /feed`.

### 🟥 Agent E — Соц-слой и состояние
- Лайки / сохранить-в-избранное / «не интересно» поверх существующей авторизации и favorites.
- Персист на юзера, синк между лентой и страницей фильма. **Зависит от:** B, существующая авторизация.

### 🟪 Agent F — Аналитика и тюнинг
- Метрики: доля долистываний, средний %досмотра (★ северная звезда), конверсия трейлер→«Смотреть»→просмотр, скорость сходимости, разнообразие.
- Дашборд + A/B (контентный скоринг vs +CF). Подбор весов награды. **Зависит от:** B (события).

### ⬜ Agent G — Мобильное (Фаза 4)
- `react-native-video-feed` в Expo-приложении, тот же `GET /feed` API. **Зависит от:** B, C.

### Порядок и зависимости
```
A (каталог) ─┐
B (API+события) ─┬──► C (лента UI) ─┐
              └──► D (рекомендатель) ─┴──► F (метрики/тюнинг)
E (соц-слой) параллельно (нужна только авторизация)
G (mobile) — после C, Фаза 4
```
**Критический путь:** B → (A,C,D) → F. A и E можно параллелить с B.

## 7. Риски / на что смотреть
- **Покрытие трейлерами:** не у всех фильмов есть TMDB-трейлер (особенно старое/нишевое) → фолбэк на популярные / англ. трейлер / скрывать без трейлера.
- **YouTube-embed ограничения:** часть видео `embedding disabled` → фильтровать на этапе каталога (Agent A).
- **Автоплей на мобиле:** только muted (политика браузеров) — ОК, как в TikTok.
- **Холодный старт:** первые ~12 карточек — популярное + жанровая «разведка», сходимость за 10–20 свайпов.
- **Без отрезков фильмов** в Фазе 1 → ноль нового legal-риска (трейлеры — промо, embed).
