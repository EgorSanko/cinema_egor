# Полный переход с TMDB на HDRezka — план миграции (все поверхности)

> Ветка `hdrezka-migration`. Цель: **убрать TMDB полностью** во всём продукте — сайт, «Вместе», свайп, ТВ-обёртка, мобильные приложения. Вести весь каталог/метаданные от HDRezka.
> Прод (`revamp`) не трогаем — вливаем «по щелчку», когда весь чек-лист зелёный.
> Обновлено 2026-07-02 после research HDRezka + решений владельца.

## Решения владельца (2026-07-02)
1. **История/избранное — ПЕРЕНОСИМ** (не сбрасываем). Фоновый маппинг `tmdb_id → hdrezka_id`: при первом входе для каждого старого id один раз резолвим название→HDRezka→id, кэшируем. Никто ничего не теряет.
2. **Роутинг карточек — оставляем `/movie/[id]` и `/tv/[id]`** (id теперь = HDRezka numeric id). Минимум переделок, SEO-структура цела. (решил за владельца по его просьбе)
3. **MovieTok (`/feed`) — УДАЛЯЕМ ПОЛНОСТЬЮ.** «Никому не зашла, бесполезна.» → не мигрируем, вырезаем.
4. Охват — **весь продукт**, не только сайт: сайт + «Вместе» + свайп + ТВ + приложения. Фаз должно быть много; по ходу вычищаем ненужное.

## Новые эндпоинты бэкенда (kino-api `hdrezka_server.py`)
Кэш как у `/api/find`/`/api/details`, лёгкие read-only фетчи (бокс 4ГБ — без тяжёлого).
1. `GET /api/browse?cat=&sort=latest|popular|watching|best&genre=&year=&page=` → карточки витрины.
2. `GET /api/card?url=` (расширить `/api/details`) → полная карточка (ratings/persons/directors/collections/franchise/rankings/age/genres/…).
3. `GET /api/trailer?url=` → `{youtube_id}`.
4. `GET /api/person?url=` → актёр + фильмография.
5. `GET /api/franchise?url=` / `GET /api/collection?url=` → части серии / тематическая коллекция.
6. `GET /api/genres` → фикс-список жанров HDRezka (name+slug).
7. `GET /api/map?tmdb=&type=` → фоновый маппинг tmdb_id→hdrezka (для миграции истории). Кэш навсегда.
Уже есть: `/api/find` (поиск), `/api/episodes` (сезоны/серии), `/api/resolve` (стрим по url).
